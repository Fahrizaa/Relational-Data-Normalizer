Transparansi Privasi & Keamanan Kunci API

Aplikasi ini dirancang sebagai proyek open-source yang berjalan 100% di sisi klien (Client-Side Architecture).

  • Mengapa Memerlukan API Key Mandiri? Website ini di-host secara publik via GitHub Pages tanpa server terpusat/backend. Menyediakan API Key sentral milik pengembang akan mengakibatkan kuota cepat habis (rate limit) dan risiko pembengkakan biaya tagihan yang tidak realistis untuk proyek nirlaba. Model mandiri ini adalah solusi yang adil dan berkelanjutan bagi seluruh pengguna.
  • Jaminan Privasi & Keamanan: API Key Anda tidak pernah dikirimkan ke server kami atau pihak ketiga mana pun. Kunci hanya disimpan di localStorage peramban Anda dan dikirim langsung dari browser Anda ke endpoint resmi Google Cloud API (generativelanguage.googleapis.com) menggunakan protokol enkripsi HTTPS aman.

Formulasi UNF, 1NF & Penentuan Primary Key

Tahapan transformasi data dari bentuk non-normal (UNF) ke bentuk normal pertama (1NF).

Unnormalized Form (UNF)

Mengelompokkan data menjadi Atribut Header (Nilai Tunggal) dan Kelompok Berulang (Repeating Group) sebelum proses atomikasi.

First Normal Form (1NF)

Menghilangkan kelompok berulang sehingga setiap sel bernilai atomik. Pilih Primary Key dengan mengklik tombol kolom di bawah.

Normalisasi 2NF & 3NF

Dekomposisi tabel relasional lengkap dengan pemisahan ketergantungan parsial (2NF), transitif (3NF), serta penetapan Primary Key (PK) dan Foreign Key (FK).

Status Kunci: PK: Primary Key (Kunci Utama) FK: Foreign Key (Kunci Tamu / Asing) Kolom PK tabel master yang dirujuk tabel lain berstatus sebagai FK

Second Normal Form (2NF)

Memisahkan ketergantungan parsial dari Composite Primary Key.

Third Normal Form (3NF)

Memisahkan ketergantungan transitif pada atribut non-primary key.
